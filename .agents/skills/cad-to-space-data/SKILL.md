# CAD 图纸转可维护空间数据

目标：建立可靠的空间事实，让后续设计和建模知道哪些信息已确定、哪些有矛盾、哪些仍未知。

开始前读取[共享数据约定](../../../reference/space-workflow-contract.md)。输入为有效图纸及已有项目数据；输出为源图索引、空间数据、核查记录和未知项。

## 流程

1. **确定有效资料。** 区分原始图、设计图、拆改图和实测资料。读取当前项目说明及用户最新要求，排除已废弃方案。备份涉及的现有结果，保留原始文件。
2. **转换并检查损失。** 按本机可用工具处理 DWG/DXF/PDF；不假定存在某个转换器。核对图块、嵌套实例、文字、尺寸、线型、圆弧和图形范围。转换成功不等于完整；匿名块丢失、镜像/旋转变换、OCS/WCS 混用须结合原图定位。缺工具时保留可处理成果，说明缺少的能力或所需导出格式。
3. **建立坐标与来源。** 明确单位、各层原点、轴向及变换。展开图块时保留实例路径、句柄和属性；原始图元与语义构件分开保存。多层对齐后以独立锚点复核，不用移动井道掩盖差异。
4. **识别构件与关系。** 结合图例、完整符号、位置和相邻对象识别墙柱梁、门窗、楼梯、井道、挑空、家具及设备。颜色只能作为项目线索；圆角不能直接当门弧，柜体散线不能因不是图块而遗漏。明确开口宿主、门扇开向和空间连通关系；未确认的分类保留待核状态。
5. **核查平面与竖向。** 核对尺寸链、总尺寸、墙厚、洞口、房间边界及注明面积。收集标高、层高、净高、梁底、板和局部高差；保留标注原文，不把不明数字直接解释为构造尺寸。检查楼梯、夹层、挑空、柱及管井的上下层对应。
6. **记录用户补充的竖向条件。** 允许按朝向或构件组记录用户明确给出的统一窗台高、窗高和落地窗条件，并注明适用范围。分别记录层高、净高与吊顶完成面。平面截图缺少可靠比例时，优先用标注尺寸或已知基准校准，关键开间、轴向或洞口位置无法判定时列出需确认的问题。
7. **对照并交付。** 逐层叠加源图与生成几何，同时检查“生成对象有没有依据”和“源图重要对象有没有遗漏”。用局部放大核查可疑点，保留差异清单；不能只靠实体总数证明还原准确。

## 完成标准

- 主要构件可回溯来源，源图中未建入的内容有记录；输出可重新生成和修改。
- 单位、坐标及楼层对齐依据明确；尺寸与空间关系的冲突未被静默抹去。
- 未知尺寸未填成事实。若进入预览，假设独立保存并传给下游。
- 交付可查看的平面对照、可维护数据、核查记录及后续最需要补充的资料。

## 仓库资源（按需）

- CAD 语义：[cad-conventions.md](../../../reference/cad-conventions.md)。图例是线索，仍以当前图纸证据为准。
- 复杂图块：[route-dxf-layout.md](../../../reference/route-dxf-layout.md)；多层：[route-building.md](../../../reference/route-building.md)。
- 数据接口：[structure-format.md](../../../reference/structure-format.md) 与 [structure.schema.json](../../../reference/structure.schema.json)。二维线框不自动升级为已核实的空间实体。
- 公共工具：[toolkit/README.md](../../../toolkit/README.md)；`cad inspect` 保留图元和来源，`cad view` 生成对照页。空间实体接口见 [数据格式](../../../toolkit/schemas/README.md)。
- 早期识别脚本通过 `space.mjs run` 调用，先读 [兼容范围](../../../toolkit/legacy/README.md)。`build_walls.py` 属于特定图纸的项目实现，不随公共包发布，也不作为通用识别模板。

工具替代不改变上述来源保留与核查要求。

## 构件分类与着色交付

原图核对 HTML 同时提供构件分类视图与原线稿对照。将类别、判定依据、待核状态和源图元 ID（含块实例路径）保存在可单独维护的分类文件中，预览读取同一份映射。逐项校验覆盖和重复归类。图例标明计数单位，可切换类别、点选查看来源。

梁线与梁高标注、门扇与窗带、实体墙轮廓与柱墩分别识别。混用图层或同色时按完整符号、洞口和邻接几何分辨。墙体类别另分已确认承重、已确认非承重、承重待核；确认需结构图、明确图例或可靠的逐段记录。证据不足的门窗组合、推拉扇及其余细节保留待核类别。项目专用句柄、颜色和映射放在项目目录。
