# 设计图像出图

本 skill 负责把已经确定的空间和固定机位转成平面彩图或氛围效果图。基础图锁定几何，风格图只提供材质、色彩、光线和软装语言。它不改变墙体、门窗、家具位置或三维模型。

设计器已有的 colorplan 是确定性渲染，适合尺寸、房间名和标注要求准确的标准彩平；本 skill 用于需要风格意向、材质氛围或生图模型的彩平和效果图。能由现有渲染直接满足的任务，先用现有渲染，避免用生成图替代可核对的数据视图。

开始前读取[共享数据约定](references/space-workflow-contract.md)和[出图 prompt 模板](references/design-image-prompts.md)；执行生图时同时遵循可用的 imagegen skill，默认使用宿主提供的内置生图工具。

## 输入

- 基础图：白模正投影、三维固定机位渲染、平面核对图或已有基础彩平。每张图必须说明它控制的是几何、构图还是材质。
- 风格意向图：一张或多张风格参考。只提取材质、配色、灯光、软装和收口方式，不据此搬入新的家具、门窗或墙体。
- 设计数据：房间名、面积、尺寸、标注和需要叠加的文字。标注优先由矢量或文字图层叠加，不要求生图模型生成精确文字。
- 任务类型：color-plan、interior-perspective、dollhouse、elevation 或 material-detail。

缺少基础图、固定机位或足以确定空间关系的数据时，先回到 plan-to-3d 补齐；不要用一张风格图凭空生成一张“看起来像这个户型”的图。

## 流程

1. 固定输入版本。记录项目、设计版本、基础图路径与哈希、风格图路径与用途、目标尺寸和参考机位。旧图保留，新图使用版本化文件名。
2. 判断生成方式。需要保持几何和机位时，以基础图为主图做受约束的改写；只把风格图作为材质和光线参考。多张风格图分别标注用途，例如“墙面与柜体材质”“灯具与软装”“整体色温”。
3. 选择模板。从[出图 prompt 模板](references/design-image-prompts.md)选择对应任务，填入空间、材质、光线、构图和禁止项。模板不是装饰性文案，必须保留“不得改变几何”的约束。
4. 调用生图工具。使用宿主可用的 imagegen 工具。内置工具不可用时，说明具体失败；CLI/API 回退需要用户明确同意，不能静默切换模型或服务。
5. 验收。将成图与基础图叠合或并排检查墙体、开口、家具数量与位置、镜头边界、柜体分格和文字。发现几何漂移时重新生成，不用“氛围更好”掩盖结构变化。
6. 叠加标注。彩平图的房间名、面积、尺寸线、指北针和比例尺由设计数据生成并叠加。不要依赖模型生成中文或数字，避免错字和尺寸错误。
7. 保存与登记。输出图、prompt、参考图角色、生成参数、验收结果和未解决项一起保存。AI 成图是表现层派生结果，不能反向覆盖空间数据或三维工程。

## 任务与约束

| 任务 | 基础图 | 必须保持 | 主要输出 |
|---|---|---|---|
| color-plan | 正上方正交投影 | 墙线、开口、家具占地、房间边界 | 有材质的彩色平面图 |
| interior-perspective | 固定机位三维渲染 | 机位、焦距、墙窗、家具位置 | 室内氛围效果图 |
| dollhouse | 鸟瞰或轴测白模 | 平面关系、层高和开洞 | 剖切鸟瞰图 |
| elevation | 正立面或柜体立面 | 柜体分格、层板、门缝、收口 | 材质立面图 |
| material-detail | 近景渲染或材质样板 | 构件边界、纹理尺度和收口 | 材质细节图 |

彩平图必须正交俯视，不出现透视、天花板、吊灯或漂浮物。室内效果图必须保留基础图的镜头和空间边界，不新增门洞、窗洞、房间或家具。鸟瞰图不改变楼层关系和挑空。立面图不改变柜体模块和层板标高。

## 验收

- 基础图与成图的墙体、开口、家具数量、主要轮廓和镜头边界一致。
- 风格图只影响材质、配色、灯光、软装和表面质感，没有把参考图的户型搬进来。
- 垂直线保持垂直，镜头没有夸张广角、鱼眼或结构拉伸。
- 彩平图没有透视，没有天花和悬挂物，标注来自数据而不是模型猜测。
- 文字、数字、指北针和尺寸线单独核对；不把模型生成的文字当成设计数据。
- 输出文件实际存在，分辨率、色彩和透明背景符合任务要求，资源没有只留在临时目录。

## 与同步入口衔接

design-to-3d-sync 在固定机位渲染完成后调用本 skill。基础图使用本次固定机位或正交底图；风格图使用项目登记的风格意向图；输出写入同步版本的 visuals 目录，并在 render-manifest.json 中登记。

AI 成图不替代固定机位渲染、平面核对或三维工程检查。同步状态只有在三维工程和固定机位通过后才可写 passed；visuals 的生成状态单独记录。

## 输出

在 output/<project>/design-sync/<version>/visuals/ 下保存：

- <visual-id>.png：成图。
- render-manifest.json：基础图、风格图、prompt、工具/模型、尺寸、种子（如有）、验收状态和未解决项。
- overlay-<visual-id>.png 或并排对照图：几何验收记录。
- notes.md：风格图的使用方式、被放弃的生成结果和需要用户确认的事项。
